## The rules behind the grid

- **A personal account on every system.** Never a shared login, never the founder's login. On Seller Central that is a secondary user on {first_name}'s own work email, invited through Settings, User Permissions.
- **Least privilege for the first task.** The first task is mapping work, which needs reading. View first, on the pages that task needs.
- **Seller Central stays view only until approved.** Edit arrives per task, after the day-7 call, when {signoff} has approved it. Never Administrator. Never banking, deposit, tax or account information.
- **A password manager for every secret.** A team plan owned by the founder, one shared vault per system area, {first_name}'s own private vault, and an expiring share for a one-off secret. Set up before the offer goes out.
- **Two-factor authentication on every login**, on an authenticator app, not SMS.
- **No credentials in chat or email, ever, in either direction.** Pasting a password into a chat is the biggest day-one risk, and it is usually the founder who does it.
- **Access grows with the responsibilities.** The ladder is tied to the day 7 and day 30 checkpoints and written into the onboarding document, so it reads as a plan, not distrust.
- **Company-owned accounts.** Domains, ad accounts, drives, the mailbox: all under {brand}'s accounts.
- **Review at day 30, day 90, then every six months** and at every role change. First six-month review: {review_6m_long}. Anything not used is removed.
- **Agencies and outside tools go through Authorized Partners** or the tool's own integration, never through a user login.
- **The first security conversation is the anti-phishing talk** (`phishing-talk.md`), because the documented takeover vector is a phishing email, not a permission set too wide.
